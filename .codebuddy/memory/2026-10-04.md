## 清理 git 提交信息里误带的 ``` （两轮 filter-branch）
- 起因：多笔提交信息开头/结尾被误写了 ` ``` ` 围栏（单独一行），加上正文里本来就有正常的分段空行。仓库无远程（`git remote -v` 为空），只影响本地。
- 做法：重写 master 全部 39 个提交（其中 23 个含围栏）的信息，**只改信息、不动任何文件内容**（`tree` 哈希前后一致，可校验）。**最终要求：信息里既无 ``` 也无任何空行**（用户明确"不要留空行"）。
  - 第 1 轮：`tr -d '\140' | sed 's/^ //'` 去反引号字符。但围栏是**独占一行**的，删掉字符后那两行变成**空行**，残留多余换行。
  - 第 2 轮：awk 剥掉首尾空行、保留正文内部分段空行——用户仍不满意（分段空行也不要）。
  - 第 3 轮（定稿）：`awk '{ if ($0 !~ /^[[:space:]]*$/) print }'` —— **只输出非空行**，所有空行（首尾+分段）一并去掉。每行以单个 \n 结尾，仍是标准 commit 结尾。
- 恢复点：`backup-before-msg-cleanup`（原始历史，指向重写前 3102a31）。`refs/original/refs/heads/master` 在后续轮次被 `-f` 覆盖成中间态，不是原始，要回退用命名分支。
- 校验：`git rev-parse 'master^{tree}'` 与备份分支的 tree 相同 = 内容未变；`git log --oneline | Select-String '```'` 计数为 0；`git rev-list --count` 仍 39。

### 踩坑（PowerShell + git，可复用）
- **`filter-branch` 的 msg-filter 执行时工作目录不是仓库根**（在 `.git-rewrite` 临时目录里），所以 `--msg-filter "sh .git/x.sh"` 会报 `No such file or directory`；要写**绝对路径**（Git Bash 认 `D:/...` 正斜杠盘符）。
- **PowerShell 里 `echo ===X(abc)===` 会炸**：`(abc)` 被当成命令调用。改用不带括号的 `echo`，或用 `Write-Output`。
- **PowerShell 内嵌 `$(...)` 里再套 `.Count` / `^{tree}` 会被解析坏**（`^`+`{}` 被当脚本块，触发 `-encodedCommand` 注入）。改为分步赋值 + `Write-Output`，`^{tree}` 用**单引号**包住。
- `refs/original/` 已存在时 `filter-branch` 会拒绝，需 `-f` 覆盖（或先 `git update-ref -d`）。
- msg-filter 里**别写字面反引号**（shell 命令替换）也**别让 PowerShell 展开 `$0`**（awk 变量）；反引号用八进制 `\140`（=0x60）表示，awk 脚本放文件里、用绝对路径调用最稳。

## 功能：慢双击进入重命名（Explorer 手势）
- 需求：用户要求能"双击文件夹进入重命名模式"（口语，指 Explorer 那种**单击选中→停顿→再单击同一项**= 重命名的手势）。
- 原有行为：双击=打开/进入（`NM_DBLCLK`，MainWindow.cpp），重命名只能靠 F2 / 右键菜单。
- 实现（`src/UI/MainWindow.h` + `MainWindow.cpp`）：
  1. 新增成员 `lastRenameList_ / lastRenameClickItem_ / lastRenameClickTime_`，常量 `kSlowRenameWindow = 1500`。
  2. `ListViewProc` 里处理 `WM_LBUTTONDOWN`（在分隔条命中判断之后）：`LVM_HITTEST` 取行下标，用 `GetMessageTime()` 判时间——若**同一列表同一项**、该项已选中、间隔 **≥ 系统双击时间且 ≤ 1500ms**，则调 `RenamePath()` 并 `return 0` 吃掉这次点击。
- 原理：快速双击会被系统判成 `WM_LBUTTONDBLCLK`（走 NM_DBLCLK 打开），**慢**的第二次点击才会以 `WM_LBUTTONDOWN` 到达，所以只在这一条路径上拦截，两者不冲突。
- 细节：Ctrl/Shift 为选择修饰键，命中时清空记录不触发（避免多选后误重命名）；`lastRenameList_` 记录列表句柄，**多窗格之间不会串**；触发后复位防止连点连续弹框。
- 编译链接通过（仅既有 warning）。手势涉及时序，自动化不好验，建议用户手动试：选中→停 ~1s→再单击 = 弹重命名；快速双击仍进入文件夹。

## 修复：Alt+↑（上级）无法从一级文件夹退到盘符
- 现象：在 `F:\tts_out` 按 Alt+↑（或"↑"按钮）没反应，**一级文件夹退不到盘根 `F:\`**。
- 根因（`MainWindow.cpp` `WM_COMMAND` 的 `IDC_UP`）：原逻辑 `size_t p = dir.find_last_of('\\'); if (p != npos && p > 2) Navigate(dir.substr(0, p));`。
  对 `F:\tts_out`，最后一个 `\` 在下标 **2**，于是 `p > 2` 为假 → 被误拦。`p > 2` 本意是防止越过盘根，但对"父目录就是盘根"的一级文件夹恰好误杀（`C:\Users`、`D:\foo` 等同理都上不去）。
- 修复：改为显式判断——先去掉尾部 `\`/`/`，若 `end <= 2` 说明已在盘根则不动；否则取最后分隔符前一段，若只剩盘符（长度 2）就补 `\`（`F:` → `F:\`），再 `Navigate(parent)`；`parent == dir` 时不重复导航。
  - 现在：`F:\tts_out`→`F:\`✓；`F:\`→`F:\`（停住）✓；`F:\a\b`→`F:\a`✓。
- Alt+↑ 与"↑"按钮共用 `IDC_UP`（加速键 `Alt+↑`→IDC_UP），一处修好两处生效。编译链接通过；连发 4 次 Alt+↑ 进程存活、能走到盘根不崩。

## 调整：右键菜单"Open"分组的归类规则
- 需求：把 **IDA Pro (32/64) 移进 "Open" 分组**；把 **Open With Notepad++ / Open with Sublime Text / VSCode 移出 "Open"**（留顶层）。
- 定位：`src/Shell/ShellContextMenu.cpp`。这是 PagedExplorer **自绘**右键菜单（不是改系统注册表）：
  - `IsOpenAction(text)` 决定哪些项算"open 动作"；`GroupOpenActions(menu)` 把这些项移进一个标题为 **`Open`** 的子菜单（`openItem.dwTypeData = L"Open"`，插在第一个被移项的位置）。匹配在**小写化后**做。
  - 原规则：`open in ` / `open with ` / `open git gui here` / `open git bash here` / (`visual studio`+`打开`) / (`code`+`打开`) / (`workbuddy`+`打开`)，`everything` 排除。
- 改法（`IsOpenAction` 内按顺序加判断）：
  1. 排除（留顶层）：`notepad++` / `notepad+` / `sublime` / `vscode` / `vs code` / `visual studio code` → `return false`。
  2. 归入：`ida pro` / `ida32` / `ida64` → `return true`。
  3. 其余保持原规则。
- 匹配都是子串包含、大小写不敏感；IDA 的友好名是 `IDA Pro (32-bit)`/`IDA Pro (64-bit)`，命中 `ida pro`。编辑器默认带 `Open with …` 前缀会被归组，所以要用排除规则"移出"而不是删通用规则（否则其它 open with 项也会散掉）。
- 编译链接通过。归类依赖用户系统实际注册的应用名，建议右键真实文件确认一次。
- 追加需求（用户给了实际菜单截图）：再把 **VLC**（`Add to VLC media player's Playlist` / `Play with VLC media player`）、**ChatGPT**（`Open project in ChatGPT`）、**Windows Media Player**（`添加到 Windows Media Player 列表` / `使用 Windows Media Player 播放`）并入 Open；Git 的 `Open Git GUI/Bash here` 也要进。
  - 又加规则：`vlc media player` / `chatgpt` / `windows media player` → `return true`。
  - **关键修复**：`IsOpenAction` 归一化时**去掉加速键 `&`**（原来只做小写化）。因为有的菜单项写作 `Open Git &GUI here`，带 `&` 会让 `open git gui here` 子串匹配失败——这正是 Git 项明明有规则却没被归组的原因。现在改成逐字符 push（跳过 `&`、其余小写化）。
  - 注意：`IsRenameLabel` 是把 `&` 换成**空格**（因为 `重命名(&M)` 要匹配 `rename`），而 `IsOpenAction` 需要**删除** `&`（否则 `git &gui`→`git  gui` 双空格仍匹配不上）。两者处理不同，别照抄。
- 后续微调：用户又把 **`Open in Terminal`** 和 **`通过 Code打开`** 要求"移出 Open"（留顶层）。
  - 原因：`Open in Terminal` 命中通用规则 `open in `；`通过 Code打开` 命中 `(code + 打开)`——都已被归组，所以要**加排除**而不是删通用规则（删了会波及 `open in ` 其它项）。
  - 排除块再加：`terminal`，以及 `(code && 打开)` 组合——后者正好等价于把 VSCode 中文项从"归组"里挑出来，且因要求同时含 `code` 和 `打开`，不会误伤 `Encode` 之类只含 `code` 的项。
  - 至此 `IsOpenAction` 的判断顺序：**排除块 → IDA 归入 → VLC/ChatGPT/WMP 归入 → 通用规则**。改任何一条前先想清楚会连带影响哪些项。
