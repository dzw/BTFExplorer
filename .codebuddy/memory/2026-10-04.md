## 清理 git 提交信息里误带的 ``` （两轮 filter-branch）
- 起因：多笔提交信息开头/结尾被误写了 ` ``` ` 围栏（单独一行），加上正文里本来就有正常的分段空行。仓库无远程（`git remote -v` 为空），只影响本地。
- 做法：重写 master 全部 39 个提交（其中 23 个含围栏）的信息，**只改信息、不动任何文件内容**（`tree` 哈希前后一致，可校验）。**最终要求：信息里既无 ``` 也无任何空行**（用户明确"不要留空行"）。
  - 第 1 轮：`tr -d '\140' | sed 's/^ //'` 去反引号字符。但围栏是**独占一行**的，删掉字符后那两行变成**空行**，残留多余换行。
  - 第 2 轮：awk 剥掉首尾空行、保留正文内部分段空行——用户仍不满意（分段空行也不要）。
  - 第 3 轮（定稿）：`awk '{ if ($0 !~ /^[[:space:]]*$/) print }'` —— **只输出非空行**，所有空行（首尾+分段）一并去掉。每行以单个 \n 结尾，仍是标准 commit 结尾。
- 恢复点：`backup-before-msg-cleanup`（原始历史，指向重写前 3102a31）。`refs/original/refs/heads/master` 在后续轮次被 `-f` 覆盖成中间态，不是原始，要回退用命名分支。
- 校验：`git rev-parse 'master^{tree}'` 与备份分支的 tree 相同 = 内容未变；`git log --oneline | Select-String '```'` 计数为 0；`git rev-list --count` 仍 39。

### 踩坑（PowerShell + git，可复用）
- **`filter-branch` 的 msg-filter 执行时工作目录不是仓库根**（在 `.git-rewrite` 临时目录里），所以 `--msg-filter "sh .git/x.sh"` 会报 `No such file or directory`；要写**绝对路径**（Git Bash 认 `D:/...` 正斜杠盘符）。
- **PowerShell 里 `echo ===X(abc)===` 会炸**：`(abc)` 被当成命令调用。改用不带括号的 `echo`，或用 `Write-Output`。
- **PowerShell 内嵌 `$(...)` 里再套 `.Count` / `^{tree}` 会被解析坏**（`^`+`{}` 被当脚本块，触发 `-encodedCommand` 注入）。改为分步赋值 + `Write-Output`，`^{tree}` 用**单引号**包住。
- `refs/original/` 已存在时 `filter-branch` 会拒绝，需 `-f` 覆盖（或先 `git update-ref -d`）。
- msg-filter 里**别写字面反引号**（shell 命令替换）也**别让 PowerShell 展开 `$0`**（awk 变量）；反引号用八进制 `\140`（=0x60）表示，awk 脚本放文件里、用绝对路径调用最稳。
