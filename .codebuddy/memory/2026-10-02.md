## PagedExplorer：多窗格布局功能收尾（Alt+1~4 / 品字↔倒品 / 持久化）

需求：Alt+1~4 切 1~4 窗格；2=左右；3=品字(1上2下) 或 倒品(2上1下)，Alt+小键盘8/2 互换，默认上次布局、无记录用倒品；4=田字。原框架已有但跑不起来。

完成的内容：
- **启动崩溃（关键）**：`Layout()` 在第一个窗格创建前就被 `SwitchSideTab()` 调用，此时 `panes_` 为空，代码落进「4 窗格田字」分支里的 `rowW(0,1)` → 越界 AV。
  修法：把最后的 `else` 改成 `else if (n >= 4)`，n==0 时不走任何分支。（排查方法：临时 `#include <cstdio>` 打点 + `SetUnhandledExceptionFilter` 落ത്ത文件，定位到 CreateSidePanel。）
- **每个新窗格内容空白**：`BuildImageList()`/`InsertColumns()` 原来硬写 `panes_[0].list`，第 2+ 个窗格没列没图标，同时 pane0 被反复插列。改成接受 `HWND list` 参数，系统图像列表用成员 `sysImgs_` 取一次共用。
- **`UpdatePaneVisibility()` 只隐藏不恢复**（调用后窗格永久消失）：删掉该函数，改为 `Layout()` 每次都 `ShowWindow(p.tab, SW_SHOW)`。
- **窗格控件 ID 会重复**：删除窗格后下标重排导致新窗格复用已用 ID。给 `Pane` 加 `tag`（`AllocPaneTag()` 取 0~7 中未占用值），控件 ID 用 tag；`WM_NOTIFY` 里改用 hwnd 反查窗格（`PaneOfList`/`PaneOfTab`），不再依赖 `idFrom` 区间。
- **`listOldProc_` 被各窗格互相覆盖**：改为每个 `Pane` 自存 `listOld`，`ListViewProc` 增加 `HWND h` 参数按来源窗格回调原过程。
- **非激活窗格显示错数据**：`LVN_GETDISPINFO` 原来固定读 `CurTab()`。改为读本窗格自己的 `PaneActiveTab(pi)`（并用 `PaneItemPath` 取右键双击路径）；只有非 GETDISPINFO 的通知才 `SelectPane(pi)`，避免重入。
- **持久化**：favorites.txt 增加 `panes=N`、`tri=T` 配置行（`LoadFavorites` 里任意位置识别，`SaveFavorites` 用 putLine 统一写）。启动时 `ApplySavedLayout()`（只做一次）。
- **快捷键可靠性**：焦点在 ListView/Edit 上时 Alt+ 按键不会转到主窗口 → 这些组合必须放进 `main.cpp` 的加速键表（IDC_LAYOUT1~4、IDC_TRI_PINTOP/PINDOWN），同时在 `WM_SYSKEYDOWN` 保留兜底；新增 `WM_SYSCHAR: return 0;` 去掉无菜单窗口的提示音。Alt+↑ 与 Alt+小键盘8(NumLock关) 冲突 → 保留导航，额外把 Alt+↓ 也绑成“倒品”。
- 顺带修正：3 窗格品字形态的 `splitPairs_` 应为 {1,2}（原先错写成 {0,1}）且 `w` 要用 `rowW(1,2)`；分页拖拽命中改成 `PtInRect`（上下排才分得清）；重写 `CloseRightTab`（同步删除 tab 项、窗格空则 `RemovePane`）；Ctrl+点“+”限制最多 4 窗格。
- 验证：PowerShell 用 `EnumChildWindows` 数 SysTabControl32 个数（= 1+窗格数）+ `PostMessage WM_SYSKEYDOWN` 模拟按键，确认 Alt+1~4、小键盘8/2、启动恢复 panes=4 均与预期一致、无崩溃。

注意：`build.bat` 的 vswhere 路径在本机报“不是内部命令”，但后面 VS BuildTools 环境仍可用，构建正常。另外每个 execute_command 是独立 PowerShell 会话，Add-Type 的 P/Invoke 类型必须和调用写在同一次命令里。

## PagedExplorer：缩减窗格时丢弃重复目录的分页 + 首个窗格缺 tab 头

- 需求：窗格数减少时，被缩减窗格里的分页若目标窗格已有同一目录，就不再搬过去、直接丢掉。
  实现：`PaneHasDir(paneIdx, dir)`（去掉结尾多余 `\` 后 `_wcsnicmp` 比较）＋ 抽出 `RemoveTab(index, paneEmptied)`（`CloseRightTab` 也改为复用它）；`SetPaneCount` 的减少循环里先判重，重复则 `RemoveTab`，否则才 `MoveTabToPane`。
- 顺带修：**首个窗格从来没有 tab 头**——`BuildChildren` 建了 TabState 却没 `TCM_INSERTITEM`，所以 pane0 没有标题条、“+”按钮也贴到窗格最左边。现在建首个分页时补一个 tab 项。
- 验证方法踩坑：`EnumChildWindows` 会枚举到 ComboBox 内嵌的 Edit，地址栏 Edit 必须按控件 ID=1001（`GetWindowLongPtr(h,-12)`）认；`GetWindowText`/跨进程地址栏读文本不可靠，改用「各 tab 控件的 TCM_GETITEMCOUNT(0x1304) 项数」当断言。
  实测（items[0] 是左面板 2 项，其后是每个窗格的分页数）：Alt+2→[2,1,1]，Alt+1→[2,2]（不同目录正常合并），Alt+2→[2,2,1]，Alt+1→[2,2]（重复目录被丢弃，不去重的话会是 [2,3]）。

## PagedExplorer：鼠标中键点击分页标题 = 关闭分页

- `PaneTabHandler` 新增 `WM_MBUTTONDOWN`：`TCM_HITTEST` 命中哪一项 → 记到 `pendingCloseTab_` 后 `PostMessage(WM_APP_CLOSE_TAB)`，**不直接在 tab 的窗口过程里关闭**（关闭可能连带 `RemovePane` → `DestroyWindow(tab)`，不能在自身窗口过程中销毁）。
- `CloseRightTab` 里如果真的关掉了窗格，补一次 `SaveFavorites()`，让 favorites.txt 的 `panes=` 与实际窗格数一致。
- 最后一个分页不会被关掉；点标题空白处无副作用；中键被 `return 0` 吞掉（不触发系统滚动热点）。
- **调试坑（重要）**：跨进程 `SendMessage` 不能传 PowerShell 本进程 `AllocHGlobal` 出来的指针（如 `TCM_GETITEMRECT` 的 RECT），目标进程会把那个地址当自己的内存写 → 目标进程以 0xC0000409(fail fast) 崩，看起来像被测程序的 bug。
  可跨进程安全使用的：`TCM_GETITEMCOUNT(0x1304)`、`PostMessage` + 坐标、`WM_SYSKEYDOWN` 模拟按键、`ClientToScreen`/`ScreenToClient`/`GetWindowRect`（这些是 win32u 系统调用，写的是调用方内存）。
  拼 `lParam` 必须先 `-band 0xFFFF` 再移位合成，否则负数（x 为负）会把高 16 位全填 1，y 被解成 -1。
  另外 .ps1 里写中文极易变成乱码导致脚本自身解析失败，脚本一律用 ASCII 输出。

## PagedExplorer：tab 窗口过程中销毁自身导致的崩溃（拖拽分页）

用户贴的崩溃栈：栈顶在 comctl32，`PagedExplorer.exe!MainWindow::PaneTabHandler` 第 1256/1257 行（结尾的 `CallWindowProcW`）。
根因：`WM_MOUSEMOVE` 里同步调用 `MoveTabToPane`——拖走某窗格的**最后一个分页**时它会 `RemovePane`→`DestroyWindow(tab)`，
也就是在**该 tab 自己的窗口过程中把窗口销毁**，返回后 user32/comctl32 继续访问已释放的窗口结构 → 后续崩在其默认窗口过程里。

修复（和中键关闭同样的套路：破坏性操作延后到主窗口的消息循环）：
- 新增 `WM_APP_MOVE_TAB` + `pendingMoveTab_/pendingMovePane_`，`WM_MOUSEMOVE` 只记状态并 `PostMessage`，由 `WndProc` 真正执行移动。
- 拖拽状态加失效保护：`tabDragPane_`/`tabDragIndex_` 做边界检查；`RemovePane` 里清掉拖拽状态；`paneRects_` 越界防护。
- `PaneTabProc` 入口加 `IsWindow(h)` 检查，`orig` 为空时走 `DefWindowProcW`（不再 `CallWindowProcW(nullptr,…)`）。
- 验证：投递 `WM_LBUTTONDOWN`(@12,12) + `WM_MOUSEMOVE`(换算到目标窗格客户区坐标) → 日志确认 `defer move tabIndex=1 to pane=0`，结果 `tabCtl 3→2, items=[2,2]`，无崩溃；
  回归中键关闭、Alt+1~4 与缩减去重均正常。

## PagedExplorer：分页标题右键菜单（关闭/关闭其他/关闭右边/锁定）

- `PaneTabHandler` 加 `WM_RBUTTONDOWN`：`TCM_HITTEST` 命中 → `TabContextMenu()` 弹菜单（空白处右键不管，交给默认过程）。
  新 ID：`IDC_TM_LOCK/CLOSE/OTHERS/RIGHT = 1030~1033`；`TabState::locked`；`menuTab_` 记住右键落在哪个分页上。
- `CloseOtherTabs` / `CloseRightTabs` 都跳过 `locked` 的分页，并**从后往前删**（`RemoveTab` 会让后面的下标整体前移）；
  `CloseRightTab` 对 locked / 全局最后一个分页直接返回；标题前加 `[锁] ` 前缀（`UpdateRightTabLabels`）；拖拽也跳过 locked。
- 测试经验：拖动/点击某个 tab 项要精确坐标时，跨进程 `SendMessage(TCM_GETITEMRECT)` 的指针必须属于目标进程 → 用
  `OpenProcess + VirtualAllocEx + ReadProcessMemory + VirtualFreeEx` 才安全（直接传本进程指针会让目标进程崩，见上一条）。
  弹出菜单（`#32768` 窗口）用投递 `WM_KEYDOWN` 选不中菜单项（没效果），只好加临时 `WM_APP+9` 钩子直接调命令验证逻辑，验完删除。
  另外 VS 调试器会锁住 `build\PagedExplorer.pdb` 导致 `C1041` 构建失败；给 build.bat 的 cl 加了 `/FS`，并等调试会话结束再构建。

## PagedExplorer：命令行参数打开目录无效（项目已挪到 BinDir 根目录）

外部以参数 `"D:\aws\Prj\tingxiepro-uniapp" `（引号+尾随空格）启动时列表停在默认目录，两个原因：
1. `wWinMain` 手工去引号只删"恰好在末尾的引号"，尾随空格挡住 → 引号残留 → GetFileAttributesW 失败 → OpenTarget 直接返回。
2. 二次启动走 WM_COPYDATA 转发：cbData 含结尾 '\0'，接收端按 cbData/2 构造 std::wstring 把 '\0' 带进路径；
   嵌入 '\0' 使枚举 pattern = "目录\0\*"，C 字符串实际是目录本身 → FindFirstFile 返回目录自己 → 列表只有一项（目录名，即用户截图）。
修复：wWinMain 用 `CommandLineToArgvW` 取 argv[1]；WM_COPYDATA 改按 C 字符串构造 `std::wstring(lpData)`；
`NormalizePath` 顺带截断嵌入 '\0' 并去首尾引号/空白（保险）。
验证（`LVM_GETITEMCOUNT` 读列表项数）：带引号+空格 / 无引号 / 双实例转发 三种方式都正确显示 25 项，坏目录回退默认且不崩。
注意：**GetWindowTextW 跨进程读不到其它进程的控件文本**（只拿标题），地址栏读出来恒为空，不能当断言。
用户已把项目从 `BinDir\PagedExplorer\` 挪到 `BinDir` 根目录（新增 src\FileModel\ 等）；`src\main.cpp` 是不参与编译的旧版遗留。
